# Clarity Budget Feature Section

Status: File 03 Phase 5 budget feature section approved for initial landing launch.

Purpose: present budgeting as practical, user-controlled, and grounded in user-authorized transaction data without sounding punitive or overpromising automation.

## Section Role

The budget section should show that Clarity helps users set targets and compare real spending against those targets.

It should focus on:

- Monthly budgets.
- Weekly budgets.
- Custom budget periods.
- Category-level budget targets.
- Spent and remaining amounts.
- Calm progress feedback.

It should not focus on:

- Shame-based spending language.
- Automatic financial decisions.
- Guaranteed savings.
- Credit, investment, tax, or legal recommendations.
- Budget enforcement outside the user's control.

## Recommended Section Title

Preferred:

- `Set budgets that match how you actually plan`

Acceptable alternatives:

- `Track monthly, weekly, or custom budgets`
- `Compare spending against user-set targets`
- `Budget with context, not guesswork`

Avoid:

- `Stop overspending forever`
- `Let Clarity control your budget`
- `Guaranteed savings every month`
- `Never make a bad spending decision again`

## Recommended Section Copy

Preferred short copy:

> Create monthly, weekly, or custom budgets and compare user-authorized transaction activity against the targets you set.

Optional supporting copy:

> Clarity keeps budget progress visible without turning spending into a guilt loop.

## Feature Bullets

Recommended bullets:

- Set category budgets for monthly, weekly, or custom periods.
- Compare spending against user-defined targets.
- See what is spent, what is left, and what is on track.
- Review budget context alongside transactions and Rex conversations.

## Data And Control Boundaries

Budget copy must say or imply:

- Budgets are created or controlled by the user.
- Spending progress is based on transaction data available in Clarity.
- Budget status depends on categorization and available transaction history.
- Users can edit or remove budgets.

Budget copy must not say or imply:

- Clarity automatically prevents spending.
- Clarity guarantees savings.
- Clarity creates binding financial plans.
- Clarity provides regulated financial advice.
- Budget progress is exact when transaction data is delayed or incomplete.

## Screenshot Guidance

Approved screenshot concepts:

- Budget summary with synthetic monthly budget totals.
- Category budget list with synthetic category names and amounts.
- Monthly/weekly/custom controls using staged data.
- Budget performance card from the dashboard using synthetic data.

Conditional screenshot concepts:

- Keyboard-entry budget screenshots only if the keyboard does not hide important UI.
- Future-month budget screenshots only if the month label is clearly staged.

Do not show:

- Real budgets.
- Real income/spending amounts.
- Real category names tied to private behavior.
- Broken keyboard overlap.
- Empty budget states as the primary product proof.
- Toasts, debug banners, or save messages unless intentionally documenting the flow.

## Plaid Review Alignment

This section should help reviewers understand why Clarity uses transaction data:

- Connected or imported transactions power budget spent amounts.
- Categories help match spending to user-defined budget targets.
- Account connection is user-authorized and supports budget context.
- Users remain in control of budget setup and interpretation.

## Tone Rules

Use:

- `on track`
- `spent`
- `left`
- `budget target`
- `category budget`
- `compare`
- `review`

Avoid:

- `bad spending`
- `failure`
- `punish`
- `fix your habits`
- `stop yourself`
- `control your money automatically`

## Acceptance Checklist

- Shows monthly, weekly, and custom budget concepts.
- Explains budget tracking uses user-authorized transaction data.
- Avoids guilt-heavy or manipulative copy.
- Makes user control clear.
- Avoids regulated advice and guaranteed-savings claims.
